# 知识库合同（Obsidian）

以下时候读本合同：建知识库，写概念卡，给阅读笔记加双链，运行激活扩散脚本或生成知识库视图。

三个主 skill 各带一份相同的合同，由 `psychology-research-pipeline/scripts/sync_shared_literature_contracts.py` 同步。项目另有规定时，以项目为准。

## 1 库放在哪里

- **一个研究主题一个库。** 库的根目录取这个主题最上层的文件夹，要把项目文件和全文 PDF 都包在里面。这样阅读笔记里的页码能直接跳到 PDF，提纲和笔记也能互相链接。
  - 项目文件夹本身就是最上层的，用项目文件夹。
  - 拿不准时问用户一次，把答案写进项目的 AGENTS.md，以后照着用。
- **知识内容放在 `<主题>知识库/` 里。** 这个文件夹在根目录下；项目文件照旧放在原处。
- **无关文件设为排除。** 旧项目、临时文件、原始导出和旧笔记写进 `.obsidian/app.json` 的 `userIgnoreFilters`，不进搜索和关系图。全文 PDF 所在的文件夹不能排除，否则页码链接会失效。
- **只用 Obsidian 自带的功能：** 属性、Bases、反向链接、关系图、大纲，不装第三方插件。
- **初始化用脚本。** 运行 `scripts/init_knowledge_vault.py` 建好文件夹、首页、视图和 `.obsidian` 设置；已有的文件不覆盖。
- **边读边建，不预先批量建。**
  - 第一次精读时，库还不存在，先初始化，然后照常读。
  - 节点随阅读一篇一篇长出来，每篇怎么做见 3.4。
  - 用户另外要求时，才从方案里批量建种子节点。

## 2 文件夹

```text
<主题>知识库/
├── 首页.md          入口：怎么用、从哪里开始
├── 文献/            每篇精读文献一份阅读笔记
├── 概念/            构念、理论、现象、关键术语
├── 测量工具/
├── 结局/            实证论文项目可以改名为“变量”
├── 方法/            设计、模型、分析术语
├── 样本/            队列、数据集、研究家族
└── 视图/            Bases 表格视图（.base）和脚本生成的边表
```

## 3 按激活扩散模型组织节点

知识库按 Collins 与 Loftus（1975）的激活扩散模型组织：

1. **节点是概念。** 关键构念、术语、测量工具、结局、方法和样本都是节点，每个节点一张概念卡。
2. **节点之间有带强度的关联。** 概念卡里写明这个节点和哪些节点相连、是什么关系、强度多大、依据是什么。
3. **激活沿关联扩散。** 从一个节点出发，关联越强、路径越短，另一个节点被激活得越多。脚本按这个规则算出每个节点“最相关的概念”，写进它的概念卡。
4. **文献是证据。** 阅读笔记链接它用到的概念。两个概念被越多文献同时研究，它们之间的关联就越强，这一部分由脚本自动计入。

### 3.1 哪些东西要建节点

要建：
- 本领域的关键构念和理论术语，如人格功能、身份认同、同分异质；
- 文章里会反复出现的名词，如增量效度、个体内效应、测量不变性；
- 测量工具、结局（或变量）、方法和模型、重要的样本或队列。

不建：
- 只在一篇文献里出现、以后不会再用的细节；
- 普通词，如“研究”“数据”“样本量”；
- 文献本身：它已经是 `文献/` 里的节点。

**新建前先查重。** 在库里搜中文名、英文名和缩写；别名也能被搜到。已有节点的，就链接已有节点，不建同义节点。

### 3.2 概念卡怎么写

用 `templates/` 里的概念卡模板。各节要求如下：
- **一句话**：这个概念是什么，不超过 60 字。
- **是什么**：2–3 段，写定义和内涵，以及不同体系或学派怎么说。每种说法都注明来源：知识库里有阅读笔记的用双链，没有的写“作者 年份”，并标“未核对原文”。
- **在本领域怎么用**：边界、常见误用，以及和相邻概念的区别。
- **关联**：格式见 3.3。
- **证据与争议**：随阅读补充，每篇一行，写清哪些研究支持、哪些反对，格式见 3.4 第 5 步。
- **激活扩散**：由脚本维护，不手改。

测量工具卡在“是什么”一节写清这些内容：测什么构念、哪个体系、几个领域、条目数、信息源、适用年龄、主要版本和中文版。结局卡写清常用工具和分界。方法卡写清这个方法估计的是什么，以及它不能回答什么。

### 3.3 关联怎么写

在概念卡“## 关联”一节，每条关联写一行，格式固定，因为脚本要读：

```text
- [[目标节点]]｜关系｜强度｜依据
```

例：

```text
- [[人格功能]]｜上位｜强｜身份认同是 DSM-5 AMPD 自我功能的两个领域之一
- [[抑郁]]｜预测｜中｜一项控制基线的前瞻研究支持，见 [[某作者 2024 某研究#^f2|某作者 2024]]
```

关系只用以下十种：上位、下位、组成、测量、区分、共变、预测、调节、中介、对照。

强度只用三档：

| 强度 | 什么时候用 |
|---|---|
| 强 | 定义上的关系（上位、下位、组成、测量），或 3 项以上独立研究结果一致 |
| 中 | 1–2 项独立研究支持，或理论上有明确论述 |
| 弱 | 只是推测，或研究结果不一致 |

独立研究按研究家族算：同一样本的几篇报告只算一项。

几条规矩：
- 关联是双向的：A 卡里写了 B，B 卡不必再写 A，脚本两边都会算。两边都写了也不要紧，脚本取较强的一条。
- 写在哪张卡：
  - 测量，写在工具卡；
  - 上位、下位、组成，写在较窄的那个概念的卡里；
  - 预测、调节、中介，写在自变量（或调节变量、中介变量）的卡里；
  - 共变、区分、对照，写在任意一方，先看对方卡里有没有写过。
- 有阅读笔记作依据时，要在依据里链接到笔记里的发现块。
- 关系或强度随新证据改变时，直接改这一行，并在“证据与争议”里说明为什么改。

### 3.4 每读完一篇，知识库怎么长

写完阅读笔记后，按下面七步更新知识库：
- 4 级文献做全部七步；
- 3 级文献做第 1、2、3、6、7 步，第 4、5 步只对主要发现做。

1. **列节点。** 按 3.1 列出这篇涉及的节点：构念和术语、测量工具、结局（或变量）、方法和模型、样本或队列。
   - 4 级一般有 6–15 个，3 级一般有 3–8 个。
   - 明显少于这个数时，回头看是否漏了测量工具、方法和样本。
2. **查重。** 每个节点用中文名、英文名和缩写在库里各搜一遍。已有的，就用已有的名字，不另起名。
3. **新建。** 库里没有的，用概念卡模板建卡，状态写“初稿”，至少写四样：
   - 一句话；
   - 是什么，至少 1 段。定义取自这篇的，链接这篇笔记；取自别处的，写“作者 年份”并标“未核对原文”；
   - 一条关联；
   - “证据与争议”里这篇的一行。
4. **补关联。** 这篇检验了两个节点之间的关系时，在概念卡的“关联”里加一行或改一行，依据链接到笔记里的发现块。
   - 检验了关系，指 A 预测 B、A 调节 B 与 C 的关系、A 与 B 区分得开、A 与 B 相关这一类有结果的分析。
   - 已经有这条关联的，按 3.3 的强度表重新判断：累计到 3 项独立研究且结果一致的，升为“强”；出现零结果或相反结果的，降一档或改关系；改动原因写进“证据与争议”。
   - 只是同一篇里都出现、没有检验它们之间关系的，不写关联，脚本会按共现自动计入。
5. **写证据。** 在这篇真正说明了什么的节点卡里，“证据与争议”加一行：

   ```text
   - [[笔记名#^f2|作者 年份]]（方向）：在什么样本、用什么方法、得到什么结果
   ```

   - 方向只用支持、零结果、相反、混合、限定、背景。
   - 只用了某个工具，没有报告它的信效度或新发现的，不加这一行。
6. **连回笔记。**
   - 笔记属性里的构念、测量工具、结局、方法、样本，都写成双链列表；
   - 正文中这些节点第一次出现时加双链；
   - 证据提纲用块编号链接到笔记里的具体发现，如 `[[笔记名#^f2]]`。
7. **记一笔。** 在笔记的“提取记录”里写明知识库改了什么，例如：

   ```text
   - 知识库：新建 2 个（同分异质、RI-CLPM）；补关联 1 条（人格功能—抑郁）；写证据 3 处（人格功能、抑郁、LPFS-BF 2.0）
   ```

## 4 激活扩散脚本

运行方式：

```text
python scripts/spreading_activation.py --知识库 <主题>知识库
```

**什么时候运行**：每读完一批文献（约 10 篇）或每周一次即可，不用每篇都跑。

**怎么计算**：
1. **两个节点之间的强度。**
   - 写明的关联：强 = 0.9，中 = 0.6，弱 = 0.3。
   - 文献共现：两个节点被 n 篇阅读笔记同时链接时，强度 = 1 − 0.7ⁿ。
   - 两者合并：1 − (1 − 写明强度) × (1 − 共现强度)。
2. **扩散。** 从每个节点出发，最多走三步：
   - 一条路径的激活值，是沿途各段强度的乘积；每多走一步，再乘 0.7。
   - 多条路径到达同一个节点时，激活值按“至少一条路径激活成功”的概率合并，所以路径越多，激活越高。
3. **写回。** 每张概念卡的“激活扩散”一节，列出激活值最高的 10 个节点和最强路径。
   - 这一节用 Obsidian 链接（`obsidian://`），点开就能跳转。
   - 这些链接不算双链，不会把间接关联画成关系图上的直接连线。
4. **边表。** 同时输出 `视图/概念网络边表.csv`，文献星图可以直接用它。

权重是帮助联想和找文献的工具，不是统计量，不能写进论文当证据。

属性键名固定，项目可以加字段，但不改这些键名。

**阅读笔记：**

```yaml

候选编号:
作者:
年份:
期刊:
DOI:
阅读深度:
设计:
人群:

测量工具: []
结局: []
方法: []
样本: []

```

**概念卡：**

```yaml
类型: 概念     # 或 测量工具、结局、方法、样本
英文名:
aliases: []    # 英文全称、缩写、常见别称
上位:          # 双链
状态: 初稿     # 或 已核
```

## 6 视图（Bases）

`init_knowledge_vault.py` 会在 `视图/` 里建好两个视图：
- 文献总览：所有阅读笔记，可按年份、设计、阅读深度、章节、状态排序或筛选；
- 节点总览：所有概念卡，可按类型、上位概念、状态排序或筛选。按状态排序，就能看到哪些还是“初稿”或“待核”。

视图只读属性，不需要手动维护清单。新加视图时，照着已有的 .base 文件写。

## 7 关系图

初始化脚本会给关系图按节点类型着色：文献灰、概念橙、测量工具绿、结局红、方法紫、样本青。默认只显示知识库文件夹。

想看“激活扩散”的效果，打开某个概念卡的局部关系图，把深度调到 2–3：图上就是从这个节点出发能扩散到的范围。
